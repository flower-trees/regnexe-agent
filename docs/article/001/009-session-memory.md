# Session Memory：让 Agent 记住上下文和用户偏好

企业交互不是一次性的。

用户经常会连续提出问题：

```text
第一轮：帮我查一下北京今天的天气。
第二轮：那我今天适合穿什么？
第三轮：如果下午有客户拜访，需要注意什么？
```

如果 Agent 没有会话记忆，每一轮都像第一次见到用户，就无法形成连续服务。

Regnexe 支持 Session Memory，让 Agent 能在同一个 session 中使用历史上下文和用户偏好。

## 为什么会话记忆重要

很多企业场景都需要连续上下文。

客服场景中，用户不会每句话都重复问题背景。

业务助理场景中，用户会逐步补充条件。

项目管理场景中，用户希望 Agent 记住之前的任务状态。

销售场景中，用户可能先说明客户背景，再让 Agent 生成跟进策略。

没有 Session Memory，Agent 只能处理孤立请求。

有了 Session Memory，Agent 可以理解“基于刚才”“继续”“那这个方案呢”这类自然表达。

## 记住历史对话

Regnexe 可以按 session 保存对话历史。

```java
agent.execute(TaskRequest.builder()
        .sessionId("session-001")
        .goal("查一下成都近期天气")
        .build());

agent.execute(TaskRequest.builder()
        .sessionId("session-001")
        .goal("基于刚才的天气，帮我安排三天行程")
        .build());
```

第二轮请求里没有再次说明天气，但 Agent 可以从会话历史中获得上下文。

这让交互更自然，也更接近真实用户习惯。

## 记住用户偏好

Session Memory 不只保存事实，也可以沉淀偏好。

例如：

```text
用户：以后帮我规划商务行程时，优先安排客户拜访，景点只放在上午或晚上。
用户：帮我安排下周成都三天行程。
```

Agent 可以结合历史偏好，生成更符合用户习惯的结果。

这在企业助理场景中非常有价值。

不同用户、不同团队、不同角色，偏好都可能不同。

## 支持摘要式记忆

长对话如果全部塞进上下文，会带来成本和上下文长度问题。

Regnexe 可以结合会话存储和摘要机制，把长历史压缩成更适合模型使用的上下文。

这种方式适合：

- 客服长期跟进
- 项目任务追踪
- 多轮业务分析
- 个人助理偏好沉淀

它让 Agent 能在长期交互中保持上下文，而不是每次都从零开始。

## 与任务执行闭环结合

Session Memory 和 Search → Plan → Execute → Reflect 可以结合。

历史上下文会影响：

- Search 选择哪些能力
- Plan 如何理解用户目标
- Execute 如何构造工具输入
- Reflect 如何判断任务是否完成

例如用户之前说过“我关注合同条款的员工成本转移风险”，后续再让 Agent 分析报销制度时，Planner 可以更重视相关能力和输出要求。

## 商业价值

第一，提升连续交互体验。

用户不用每次重复背景，Agent 可以理解上下文。

第二，沉淀用户偏好。

长期使用后，Agent 可以更贴合用户、团队和业务角色。

第三，适合客服和助理场景。

这些场景天然需要多轮对话和持续跟进。

第四，减少重复工具调用。

已有结果可以被后续任务复用，降低成本。

第五，支持业务流程跟进。

一个 session 可以承载一段业务流程，而不只是一次问答。

## 结语

企业 Agent 不应该每次都从零开始。

Regnexe 的 Session Memory 让 Agent 能够记住上下文、历史结果和用户偏好。

这就是 Regnexe 的第九项核心商业价值：

**它让 Agent 从单次问答升级为连续服务，适合客服、助理和业务流程跟进场景。**
