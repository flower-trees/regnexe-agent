# Pause & Resume：让 Agent 长任务支持中断、审批和继续执行

企业任务很少都是一口气完成的。

很多流程中间需要等待：

- 等人工确认
- 等审批结果
- 等外部系统返回
- 等用户补充材料
- 等长时间工具执行完成
- 等业务人员决定下一步

如果 Agent 只能同步执行到底，那么它很难适配真实企业流程。

Regnexe 提供 Pause & Resume 能力，让任务可以暂停、保存状态，并在补充信息到达后继续执行。

## 为什么需要暂停恢复

企业长流程常常不是线性的。

例如合同审查场景：

1. Agent 分析合同风险
2. 发现高风险条款
3. 暂停并等待法务确认是否生成修订版
4. 用户确认后继续生成修改建议

例如差旅审批场景：

1. Agent 生成出差计划
2. 发现预算超限
3. 暂停等待主管审批
4. 审批通过后继续预订流程

这些场景都要求 Agent 能停下来，而不是强行继续。

## Regnexe 如何暂停任务

Regnexe 的任务执行状态会保存在 `TaskExecutionState` 中。

当执行过程中收到暂停信号时，Agent 可以把当前任务状态标记为 `PAUSED`，并把已经完成的轮次和工具结果保存下来。

```java
Future<AgentResult> future = executor.submit(() -> agent.execute(request));

// 另一个线程中触发暂停
agent.pause();

AgentResult paused = future.get();
```

暂停后的状态不是失败，而是一个明确的业务状态：

```text
[Execute Result] R1 PAUSED
[Agent Done    ] R1 Status: PAUSED | Rounds: 1
```

这让上层系统可以知道：任务还没结束，只是在等待下一步。

## Resume：带补充信息继续执行

暂停之后，用户或外部系统可以提供补充信息，然后恢复任务。

```java
AgentResult resumed = agent.resume(
        "session-001",
        "已确认，请继续生成修订建议，并保留原条款对照。"
);
```

Resume 的关键不是重新开始，而是在已有任务基础上继续。

它可以结合：

- 原始目标
- 已执行轮次
- 已调用工具结果
- 用户补充信息
- 当前任务状态

这样，Agent 不需要丢掉上下文，也不需要用户重新描述全部需求。

## 适合人工审批场景

Pause & Resume 对企业最大的价值，是支持人机协同。

很多流程不能完全自动化，但可以部分自动化：

```text
Agent 自动分析 → 遇到关键决策 → 暂停等待人工确认 → 继续执行
```

这比“全自动”更符合企业实际。

例如：

- 合同高风险条款是否需要重写
- 报销规则是否允许例外
- 客户报价是否超过授权范围
- 生产变更是否可以继续执行
- 代码修复是否允许提交

Agent 负责准备信息和执行操作，人负责关键决策。

## 适合异步和长流程业务

Pause & Resume 也适合异步业务。

有些任务需要等待外部系统，不能长期阻塞线程：

- 审批流
- 工单处理
- 数据同步
- 第三方服务回调
- 批处理任务

Regnexe 可以先保存任务状态，等外部事件到达后再恢复。

这让 Agent 从“聊天式助手”更接近“业务流程执行器”。

## 商业价值

第一，支持人机协同。

Agent 不必强行全自动，可以在关键节点暂停等待人类判断。

第二，适合长流程业务。

任务可以跨时间继续执行，不要求一次请求内完成所有步骤。

第三，降低业务风险。

高风险操作前可以暂停确认，避免 Agent 自动越过审批边界。

第四，提升用户体验。

用户可以补充信息后继续，不需要重新发起完整任务。

## 结语

企业 Agent 不应该只适合同步问答，也应该适合真实业务流程中的等待、确认和继续执行。

Regnexe 的 Pause & Resume 让 Agent 可以暂停、保存状态、带补充信息恢复。

这就是 Regnexe 的第七项核心商业价值：

**它让长任务支持中断恢复，适合人工审批、异步任务和企业长流程业务。**
