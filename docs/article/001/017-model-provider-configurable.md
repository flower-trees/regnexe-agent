# 模型供应商可配置：让企业拥有模型选择权

企业使用大模型，不应该被单一供应商锁死。

不同业务场景对模型有不同要求：

- 成本敏感任务需要低成本模型
- 高精度分析需要更强模型
- 私有化部署需要本地或内网模型
- 特定地区需要合规模型供应商
- 高并发场景需要稳定吞吐

Regnexe 通过 `ModelProvider` 和 `ModelSpec` 抽象模型供应，让企业可以按需切换模型。

## 为什么模型可配置重要

企业环境中，模型选择不是纯技术问题。

它涉及：

- 成本
- 性能
- 合规
- 数据安全
- 可用性
- 供应商策略

如果 Agent 框架强绑定某个模型供应商，企业后续迁移成本会很高。

Regnexe 把模型供应抽象出来，让 Agent 执行框架和具体模型解耦。

## ModelSpec：描述模型选择

`ModelSpec` 可以描述模型厂商、模型名称和参数。

例如：

```java
RegnexeAgent agent = regnexeAgentBuilder
        .withDefaultModel(Vendor.ALIYUN, "deepseek-v4-flash")
        .build();
```

对于调用方来说，模型是配置项，而不是硬编码在任务逻辑里。

这让企业可以根据场景调整模型。

## ModelProvider：适配不同供应商

`ModelProvider` 负责根据 `ModelSpec` 提供具体模型实例。

企业可以扩展它来适配：

- 云厂商模型
- 官方 API
- 私有化模型
- 内部模型网关
- 成本路由平台

这样，Regnexe 的 Search、Plan、Execute、Reflect 流程不需要关心底层模型来自哪里。

## SubAgent 可以有独立模型策略

在复杂场景中，不同能力可能需要不同模型。

例如：

- 主 Agent 使用高性价比模型负责规划
- 合同分析使用更强推理模型
- 代码工作区使用更适合代码理解的模型
- 简单查询使用低成本模型

SubAgent 可以根据配置决定继承主模型，或使用独立模型。

这为企业成本优化提供了空间。

## 商业价值

第一，避免供应商锁定。

企业可以根据策略切换模型，而不是被框架绑定。

第二，便于成本控制。

不同任务使用不同模型，减少不必要的高成本调用。

第三，支持私有化适配。

企业可以通过 ModelProvider 接入内部模型服务。

第四，提升系统弹性。

当某个模型不可用时，可以切换到备用模型。

第五，适合平台化治理。

模型选择可以纳入企业统一配置和成本管理。

## 结语

企业 Agent 平台必须具备模型选择权。

Regnexe 通过 `ModelProvider` 和 `ModelSpec` 抽象模型供应，让框架不绑定具体厂商。

这就是 Regnexe 的第十七项核心商业价值：

**它支持模型供应商可配置，便于企业做模型切换、成本控制和私有化适配。**
