# RETURN_LAST 与 SYNTHESIZE：让最终答案匹配用户真实意图

Agent 执行多个工具后，最终答案应该怎么返回？

这个问题看起来简单，其实非常关键。

有些任务只需要最后一个工具结果，有些任务必须综合多个能力输出。如果处理不好，就会出现“只返回最后结果，丢掉前面信息”的问题。

Regnexe 通过结果策略解决这个问题：

```text
RETURN_LAST → 直接返回最后能力结果
SYNTHESIZE  → 综合多个能力结果
```

## RETURN_LAST：适合简单完整结果

如果用户目标很简单：

```text
查一下北京今天是否适合户外跑步。
```

天气工具返回：

```text
北京今天晴，22 C，空气质量优，非常适合户外跑步。
```

这个工具结果本身就是完整答案。

这时不需要模型再扩写，也不需要重新组织格式，直接返回即可。

这就是 `RETURN_LAST` 的适用场景。

它的价值是：

- 更简洁
- 更低成本
- 更少幻觉
- 更接近工具真实结果

## SYNTHESIZE：适合复杂多任务

如果用户目标是：

```text
帮我查成都天气、分析差旅报销条款风险，并安排三天商务行程。
```

这个任务会产生多个结果：

- 天气建议
- 条款风险分析
- 行程规划

如果最终只返回最后一个 `travel_planner` 结果，就会丢掉天气和合同分析。

这时必须使用 `SYNTHESIZE`。

```text
[Plan Result] Selected: [get_weather, contract_analyzer, travel_planner] | Strategy: SYNTHESIZE
```

`SYNTHESIZE` 要求最终答案综合所有相关工具结果，满足每个用户要求。

## 结果策略由用户语义决定

结果策略不是固定规则，也不应该简单看工具数量。

关键要看用户的交付物是什么。

如果用户只要一个最终报告，前面的工具都是中间步骤，那么最后一个报告生成能力可能已经包含完整答案，可以用 `RETURN_LAST`。

如果用户明确要求多个交付物，就应该用 `SYNTHESIZE`。

例如：

```text
查询客户资料、分析风险、生成拜访建议。
```

最终答案应该包含三部分，因此适合 `SYNTHESIZE`。

而：

```text
收集资料后生成一份完整客户报告。
```

如果最后的报告生成能力已经整合了所有资料，则可以用 `RETURN_LAST`。

## 避免业务信息丢失

企业任务中，信息遗漏比格式不好更严重。

如果合同风险被漏掉，可能影响签约判断。

如果天气建议被漏掉，可能影响行程安排。

如果测试结果被漏掉，可能影响研发发布。

`SYNTHESIZE` 的意义，是让最终答案不只看最后一步，而是看完整任务要求。

## 代码和日志中的体现

Planner 会输出结果策略：

```text
[Plan Result] R1 Selected: [get_weather, contract_analyzer, travel_planner] | Strategy: SYNTHESIZE
```

Executor 会根据策略组织最终答案：

```text
[Execute Result] R1 SUCCESS | 天气建议 + 条款风险 + 商务行程
```

这让结果生成过程更加可控。

业务方可以从日志里看到：为什么这个任务需要综合，而不是直接取最后结果。

## 商业价值

第一，减少信息遗漏。

复杂多任务不会因为最后一个工具输出很长而丢掉前面结果。

第二，降低无谓扩写。

简单任务可以直接返回工具结果，避免模型重新加工带来的偏差。

第三，提高答案匹配度。

最终答案形式由用户真实交付需求决定。

第四，增强可解释性。

日志中明确显示 `RETURN_LAST` 或 `SYNTHESIZE`，便于排查。

## 结语

企业 Agent 不仅要会调用工具，还要知道如何形成最终答案。

Regnexe 的结果策略让简单任务保持简洁，让复杂任务完整综合。

这就是 Regnexe 的第十二项核心商业价值：

**它支持 RETURN_LAST 和 SYNTHESIZE，避免复杂任务只返回最后结果导致业务信息丢失。**
